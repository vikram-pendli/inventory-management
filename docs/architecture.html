Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI backend that serves in-memory mock data. There is no database.

System architecture

Three tiers, two processes. The browser app and the API run separately in development.

Frontend - Vite dev server, port 3000
Router (main.js)
Views: Dashboard, Inventory, Orders, Demand, Spending, Reports
Components: FilterBar, detail modals
Composables: useFilters, useAuth, useI18n
API client (api.js, axios)
HTTP / JSON over http://localhost:8001/api (CORS open to all origins)
Backend - FastAPI + Uvicorn, port 8001
Route handlers (main.py)
Query-param filtering in Python
Pydantic response models
Aggregations: dashboard, reports, spending
imported at startup
Data - in-memory, loaded once at startup

Data flow

How a filter change on the dashboard becomes updated numbers on screen.

1. FilterUser changes Time Period, Warehouse, Category or Order Status in FilterBar.
2. Shared stateuseFilters holds the four filters as module-level refs shared by all views.
3. API callThe view calls api.js, which sends the filters as query params.
4. FilterFastAPI filters the in-memory lists in Python.
5. ValidatePydantic response models validate and serialize the result.
6. RenderRaw data lands in refs; computed properties derive totals and chart series.

Things to know

  • api.js defines calls for /tasks and /purchase-orders (POST, GET, PATCH, DELETE), but main.py does not define those routes. Those calls will fail until the backend is extended.
  • Backlog.vue is not registered in the router and is not imported anywhere. Backlog data reaches the UI through the Dashboard and its detail modal.
  • Reports bypasses api.js and calls axios directly with its own hard-coded URLs.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js.
  • Inventory endpoints do not support a month filter because inventory has no time dimension.
  • All data lives in process memory, so any write is lost when the backend restarts.
